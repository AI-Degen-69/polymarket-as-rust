What the refactor actually changes — and what the riskdiff is for

Two separate things keep getting mixed together. The refactor makes one 512-line function readable and removes six copies of a 29-field struct. The riskdiff is not part of that change: it is the evidence that the change did not alter behaviour. This page shows both, with the real numbers.

The starting point

One function did everything, and every exit rebuilt the whole trace

RiskActor::step is the risk actor's per-tick entry point: it checks circuit breakers, runs the lifecycle phase machine, measures exposure, decides whether to quote, reduce or flatten, and emits a RiskActorTrace — 29 fields of telemetry — on the way out.

On main that function was 512 lines with six different return points. Each return point wrote its own full RiskActorTrace { … } literal, listing the same 16 tick-invariant values by hand. That is the actual defect being fixed: not style, but six places that must agree.

What that costs

Add one field to the trace and you edit six literals. Miss one exit and that path silently reports a different shape than the others — a telemetry bug that no test catches unless the test targets that specific exit. Two exits had no actor-level test at all: residual dust in the flatten window, and the one-shot epoch rollover.

Why it was never noticed

The exits almost always produce the same values, because most of the trace is copied from inputs. A divergence only shows up on a rare path — one that fires once per epoch, or only when a position is too small to flatten. Those are precisely the paths this refactor touches.

Change 1 · commit b54db8b

Build the trace once per tick, let each exit describe only its decision

The trace splits into two halves: what is true for the whole tick, and what this particular exit decided. The first half is captured once into a TraceCtx; the second is a small TraceExit. One builder assembles both into the 29-field record.

TraceCtx

tick-invariant

now_ms, tau_secs, breaker, the four best bid/ask quotes, start Instant. Captured once, identical for every exit by construction.

TraceExit

what this exit decided

phase, tier, utilization, action_up, action_dn, flatten_action, cancel_all_reason — 7 fields. TraceExit::placeholder() covers the exits that return before Station 7 measures exposure.

build_trace()

the only place a full record is written

A new field now means one edit in one function. The six exits cannot disagree any more, because none of them builds the record. 

// one of six, at each exit — main (fecef0d)

Change 2 · commit 4aa69e1

Lift the dense blocks out of step into named owners

Three blocks in the middle of step carried long inline reasoning. Each became a named helper with a single job and a doc comment, which is also what makes them individually testable.

fn snapshot_without_own_slots

measure exposure without counting yourself

Subtracts the actor's own live resting orders from the registry snapshot — shares, notional and the released cash — so a single-slot replacement cannot look like external exposure or committed cash.

fn send_risk_flatten

Tier-4 flatten send, with its failure path

Sends the flatten on the priority lane and reports a channel failure as a trace reason instead of dropping it. Before, that reporting was tangled into the branch that decides to flatten.

fn apply_size_overlay

phase and hedge size overlay

Applies the epoch-phase size rules and hedge skew to the risk engine's sizing decision, in one place instead of interleaved with quoting logic.

Why both captures
The real recording proves the branch behaves like main across 88,512 order events — but it never holds a one-sided position into the final 30 seconds, so it never flattens. None of the 21 recordings on disk does. The synthetic capture exists for exactly the exits the real data cannot reach: a fill, then expiry with the position open, which produced cancel_all at T−30 and a real flatten order.
